# Review Guidance

Read by every automated and human review of this repository. It defines what counts as a
failure here — findings outside it are noise.

## What this package is

`ggseg.formats` defines the `ggseg_atlas` S3 class and the contract that the whole ggsegverse
ecosystem is built on: `ggseg`, `ggseg3d`, `ggseg.extra`, and every atlas package consume it.
A change that breaks the contract breaks dozens of packages at once, and you find out from
CRAN's automated mail with a deadline attached. Treat the contract as published API, not as
internal structure.

## What counts as a failure

Report these as **Important**:

- A change to the `ggseg_atlas` contract — required columns, their types, allowed values of
  `type`/`hemi`/`side`, or the structure of the nested geometry columns — without a
  `lifecycle` deprecation path
- An S3 method added, removed, or narrowed for a class the package already supports.
  The published dispatch surface is recorded in
  `tests/testthat/_snaps/core_contract.md`, under "the published dispatch surface", and is
  generated from the live methods rather than listed here — a surface written out by hand
  drifts from `NAMESPACE` and then silently licenses the break it was meant to catch.
  **A diff to that snapshot is the finding**: it means a consumer's dispatch changed, and the
  PR must say which consumer and why. Accepting the new snapshot without that is the failure.
- Wrong results returned silently — a region renamed, dropped, reordered, or mapped to the
  wrong hemisphere while the object still validates
- A bundled atlas (`dk`, `aseg`, `tracula`, `suit`) whose region count, labels, or palette no
  longer match its source
- `legacy_region_map` changes that remap an existing label, rather than only adding new ones —
  that silently rewrites other people's published figures
- An exported function's signature, defaults, or return type changing without deprecation
- A new branch or changed behaviour with no test exercising it
- A new hard dependency in `Imports` that isn't justified in the PR description. The package
  deliberately keeps `sf` in `Suggests` — moving it, or making any code path require it
  unconditionally, is a break (see `R/sf_availability.R`)
- Locale- or platform-dependent behaviour in region sorting or label comparison
- Anything that makes `R CMD check` fail or adds a CRAN NOTE

## What is not a failure

Do not report:

- Style, naming, or formatting — `air` and `lintr` own those and run in `code-quality.yaml`
- Missing roxygen on internal (non-exported) helpers
- Hypotheticals without a concrete atlas or input that triggers them
- Performance opinions without a measured cost on a realistic atlas. Atlas objects are tens of
  thousands of rows, so a measured claim is welcome and an unmeasured one is not
- Pre-existing issues outside the diff, unless the diff makes them materially worse — tag those
  `Pre-existing` and keep them to one line each

## Evidence standard

Every finding cites `file:line` and a concrete failure scenario: a named atlas or specific input
→ the wrong output. A claim you cannot anchor to a line is not a finding.

## Nit budget

At most **3** nits per review. If there are more, report the three that matter and drop the rest.

## Paths to skip

- `man/` — generated by roxygen2
- `NAMESPACE` — generated by roxygen2
- `README.md` — generated from `README.Rmd`
- `docs/`, `inst/doc/` — generated by pkgdown
- `data/*.rda` binaries — review `data-raw/` instead, which produces them

## Paths that always get full depth

Regardless of how small the diff looks:

- `R/core_contract.R`, `R/ggseg_atlas.R`, `R/validation.R` — the contract itself
- `R/coercion.R`, `R/compat_dataframe.R` — how every other package enters and leaves it
- `R/legacy_region_map.R` — remapping is retroactive
- `R/sysdata.rda`, `data-raw/` — shipped data
- `DESCRIPTION` — dependencies, and the `sf`-in-`Suggests` boundary
- `.github/workflows/` — a broken gate is worse than a broken function
